# AGENTS.md

Thucia is a disease-forecasting library (arboviral: dengue, Zika, chikungunya) for geo-region case data. Python >=3.11 (CI runs 3.13).

## Commands

- Env: `uv sync --all-extras` then `pip install -e .` (see `dev/README.md`). No `.venv` is committed.
- Tests: `uv run pytest` (CI uses `uv run pytest --cov=thucia --cov-report=term --cov-report=html`). Heavy real-model fits are excluded by default (`addopts = "-m 'not slow'"`); run them explicitly with `uv run pytest -m slow` (CI runs `-m "slow and not network"` — the timesfm checkpoint test is marked `network`). Run `uv run pytest tests/thucia/core/models/test_wis.py::test_perfect_forecast_zero_wis` for a single test. `addopts` also loads `-p thucia_pytest_bootstrap` (see below) so `--cov=<pkg>` works locally.
- Lint/format: `pre-commit` runs `ruff`, `ruff-format`, and `reorder-python-imports` (import ordering is NOT isort/black style). Run `pre-commit run --all-files`.
- Docs are Sphinx (`docs/`), built on ReadTheDocs from `docs/requirements.txt` (myst-parser, sphinx-book-theme).
- CLI: `thucia <command>` (dashboard, cases-per-month, cases-per-week, cases-per-day, plot-*). `thucia dashboard` launches the Streamlit app.

## Architecture

- `src/thucia/core/` is the library; `viz/` is matplotlib + Streamlit.
- **Public API**: `thucia.core` is a lazy public surface — `from thucia.core import read_db, run_model, PipelineConfig, ...` (see `__all__`). Submodules load on first access (PEP 562), so `import thucia.core` stays cheap. Internal details live in the submodules.
- **Plugin architecture**: a shared `thucia.core.registry.Registry` (decorator registration by key/`ref`, `get` raising `PluginNotFoundError`) backs the covariate sources (`core/geo/plugin_base.source_registry`), cache backends (`core/cache.cache_registry`), and the models namespace (`list_models()`/`get_model()`). Sources self-register via `@source_registry.register()` at import; `plugin_loader.load_plugins()` imports each module with per-module error isolation.
- **`thucia.flow` (Prefect wrappers) was REMOVED** — it was broken, unused, and 0% covered. Prefect support should be reintroduced only as a deliberate, dedicated component (e.g. thin `@task` wrappers over `thucia.core.pipeline` stages) with tests.
- **`thucia.core.pipeline`** holds the reusable computation stages (`PipelineConfig` + `cases_per_period`, `merge_covariates`, `prepare_model_inputs`, `fit_model`, `score_model`, `aggregate_quantiles`, `build_ensemble`, `apply_residual_regression`). These are the library API; use-case parameters (cutoff, horizons, lag recipe, model lists) go in `PipelineConfig`.
- **`thucia.core.validation`** backtests the pipeline stages: `run_backtest(prepared_inputs, config, BacktestConfig(...))` sweeps cutoff dates (see `expand_cutoffs`), fits on the past only, scores the held-out window, and aggregates per-horizon WIS/RMSE/R2 plus skill relative to a reference model. It consumes `prepare_model_inputs` output (so geo/covariate merges run once), uses `db_file=None` for in-memory fits, and refuses non-fast models unless `fast_only=False`.
- **PDFM embeddings**: `prepare_pdfm_embeddings`/`prepare_embeddings` (`thucia.core.cases`) load a **user-supplied** `.nc` embeddings file — PDFM embeddings are not publicly distributed. Expected schema: one row per admin region with a geo-code column (`GID_2`) plus `feature0..feature329` columns (dimensions are batched 0-127 search trends, 128-255 maps/busyness, 256-329 weather). `prepare_pdfm_embeddings` filters to `provinces`; duplicate geo codes are treated as an encoding error — a `UserWarning` is emitted and the first occurrence is kept. `residual_regression`/`apply_residual_regression` consume the frame; provinces without embeddings are dropped with a `UserWarning` and regression continues on the rest (mirroring the old `analysis_core.py` subsampling), raising only if no province has embeddings. Duplicate geo codes there also warn and continue.
- **`pipeline/analysis_core.py` was REMOVED** (it was a 4,400-line use-case monolith of `Steps` toggle blocks; superseded by `thucia.core.pipeline` + `thucia.core.validation`). Case data lives per-country under `data/cases/<ISO3>/` with custom loaders (e.g. `data/cases/BRA/load_cases.py`). `data/` is gitignored.
- **Case data sources** (`thucia.core.cases.sources`): a plugin registry mirroring the covariate idiom — `CaseSource` base + shared `case_registry`, `load_sources()` (imports every driver, per-module error isolation), and `load_case_source(ref, **params)` returning a configured instance. Drivers are **disease-generic**: the disease is a `**params` value at fetch time, never a hard-coded constant or part of the name. `InfodengueSource` (`ref="infodengue"`) ports the old `data/cases/BRA/load_cases.py` (IBGE municipality codes → alert API → monthly cases, optional `align_admin2_regions`), fixing the old one-arg `write_nc(df)` drift — writes are now `write_nc(df, out_path)`. `load_case_source`/`load_sources` are on the public `thucia.core` surface.

## Data layer (DuckDB)

- `read_db`/`write_db` (re-exported from `thucia.core.fs` and `thucia.core.cases`) default to `.duckdb` files; the extension is appended if missing. `.nc`/`.zarr` are also supported.
- `thucia.core.fs.DataFrame` is a lazy wrapper over a DuckDB table. Access the full frame via `.df`; `write_db`/`DataFrame(df=...)` writes one table named `data`.
- Period columns (`pd.Period`, e.g. monthly case dates) are stored as timestamps + metadata in the `__column_metadata__` table and restored on read — don't bypass the wrapper when writing.
- `GID_1`/`GID_2` are stored as DuckDB ENUMs. `.append()` re-extends the ENUM to the union of stored + incoming geo codes on every write, and geo categoricals are decoded back to strings for the `INSERT` (DuckDB casts VARCHAR→ENUM at runtime; passing the raw categorical codes across pieces fails). `read_db`/`read_nc`/`read_zarr` accept `geo_col`/`geo_parent`/`migrate`: legacy files storing `GID_2`/`GID_1` are transparently aliased to those logical names on read (`migrate=True` physically renames the DuckDB columns).

## Models

- `src/thucia/core/models/` is auto-discovered: each module must expose a callable whose name matches the module name (e.g. `sarima.py` → `sarima(df, ...)`), since `models/__init__.py` imports by name. Helper modules that don't satisfy this contract must be listed in `_HELPER_MODULES` (currently `ensemble`, `quantiles`) so they aren't advertised as models; the discovery also skips subpackages (`darts`, `utils`).
- The models package uses a module-type `__getattribute__` override so `models.<name>` / `getattr(models, name)` always resolves to the model callable — even if `thucia.core.models.<name>` was imported as a submodule first (which would otherwise shadow the function).
- Model entry points share a unified interface: every model takes `df, start_date, end_date, geo_col="GID_2", geo_parent="GID_1", geo_parent_filter, horizons=[1] (a list), case_col="Log_Cases", covariate_cols, retrain, db_file, train_col, multivariate, num_samples`. `geo_col` is the forecast region, `geo_parent` its larger grouping (filter/subset column), `geo_parent_filter` the list of allowed `geo_parent` values, and `train_col` the column to fit per-region at (`None` = whole-dataset fit; the pipeline passes `config.train_col or config.geo_col`). Never introduce a scalar `horizon` param — the pipeline and backtest pass `horizons=[1,3,6,12]`-style lists to every model, and `run_model()` forwards it. (tft/tide/chronos were broken by this; keep them list-form.) `inla` keeps its own `inla(df, gid_1)` container interface.
- **Declarative dispatch (`ModelSpec`)**: model dispatch is metadata-driven, not name-special-cased. Each model module declares a module-level `SPEC = ModelSpec(name=... | family=... | fast=... | supports=... | sampling=... | extras=...)` (`core/models/_meta.py`). `supports` is a subset of `SUPPORTED_KWARGS = {"train_end_date","retrain","multivariate","samples","season_length"}`; `family` ∈ `FAMILIES = ("statistical","darts","container","external")`; `sampling` ∈ `{"quantiles","samples","none"}`. `models.get_model_spec(name)` resolves a spec lazily (defaulting to a bare `ModelSpec(name)` for ad-hoc models without one). `core.pipeline.fit_model` builds each model's kwargs from `spec.supports` (`samples` → `num_samples`), and `core.validation`'s fast-only allowlist reads `spec.fast` (baseline/movavg) instead of a hard-coded set. Adding a model with new knobs is now a one-line `SPEC`. `ModelSpec`/`get_model_spec` are on the public `thucia.core` surface.
- The canonical quantile grid lives once in `thucia.core.quantiles` (15 levels) and is re-exported via `thucia.core.models.quantiles`, `thucia.core.models.utils`, and `thucia.core.models.utils.residual_quantiles` — import it, don't redefine it. `chronos` uses a documented 13-level subset (`CHRONOS_QUANTILES`); `quantile_sum_fast` defaults to the canonical grid.
- Model input DataFrames need columns `Date, geo_parent (if declared), geo_col, future, Cases, Log_Cases` plus covariates. Covariates must be NaN-free — run `sanitise_covariates()` first and assert no NaNs. The geo column is coerced to `categorical` by `DartsBase` (models rely on `.cat` access). Geo codes are **strings**: `pipeline.coerce_geo_cols` casts `geo_col`/`geo_parent` to `str` at `cases_per_period`/`prepare_model_inputs` entry (integer loader codes like DuckDB ENUMs' would otherwise collide as per-piece `uint8` codes). `fit_model` passes `geo_parent_filter=config.adm1`, so `adm1` must hold geo-parent **codes** (e.g. GADM `GID_1`), not names — the old `lookup_gid1` name→code helper is gone.
- `run_model()` converts samples→quantiles if needed and writes `{name}_cases_quantiles.duckdb`; the file name derives from the `name` argument (the pipeline passes `model.__name__`).
- Darts-based models (sarima, tcn, tft, nbeats, nhits, tide) share `DartsBase` (`core/models/darts/`); `torch.set_float32_matmul_precision("medium")` is set at import. `timesfm` needs torch (`timesfm[torch]` extra; base deps only pull `timesfm` without torch); chronos is a separate extra.

## Geo & covariates

- Covariate plugins live in `core/geo/sources/` (`worldclim`, `edo`, `noaa`, `worldpop`); each subclasses `SourceBase`, sets a `ref`, implements `merge(df, metrics, measures, use_cache)`, and self-registers via `@source_registry.register()`. Merge via `merge_sources(df, ["worldclim.*"])`; unknown refs raise `PluginNotFoundError`.
- Sources download from geodata.ucdavis.edu and cache under the platformdirs cache dir (`~/.cache/global.Health/thucia/` on macOS), including GADM GeoPackages. WorldClim merging is the slowest pipeline step.
- `ensure_all_regions()` (formerly `pad_admin2`) pads a frame so every region in `geo_col` appears even with zero cases. The region list resolves as: an explicit `regions=` roster (keyed by `region_col`/`parent_col`, e.g. a shapefile attribute table) → the GADM admin-2 list when the geo codes are GADM-shaped (default, `iso3=` or code-prefix derived; this wins even for categorical GADM codes because aggregation re-derives categories from observed data) → a pandas categorical's `.cat.categories` as an implicit non-GADM region list → else `ValueError` (callers that want a subset simply don't run it). It must run on the raw line-list BEFORE aggregation: `aggregate_cases`' grid fill and the fs ENUM layer only ever see observed codes. `geo_parent=None` omits the parent column in padded rows; an unknown parent value is omitted rather than propagated as all-NA. Geo code tests mock `get_admin2_list` (see `tests/thucia/core/pipeline/test_pipeline_stages.py`, `tests/thucia/core/geo/test_geo.py`, `tests/thucia/cli/test_cli.py`).

## Containers & INLA

- `thucia.core.containers` auto-detects Docker, else the user Podman socket (`unix:///run/user/$UID/podman/podman.sock`). No runtime → `RuntimeError`.
- The INLA model (`core/models/inla.py`) builds and runs an R container (`core/models/inla/Dockerfile`, platform `linux/amd64`).
- `tests/thucia/core/containers/test_containers.py` builds/runs an alpine image and fails if no container runtime is running — skip it locally if Docker/Podman isn't up.

## Tests

- Unit tests under `tests/thucia/core/...` (cases, fs, models, geo, cache). `tests/thucia/core/pipeline/test_pipeline_stages.py` probes each `thucia.core.pipeline` stage in isolation (mocked GADM, small data, fast baseline fit); `tests/thucia/core/pipeline/test_pipeline_e2e.py` chains all stages end-to-end on small synthetic data (raw line-list → padded cases → mocked covariate merge → model inputs → baseline fit → scoring, plus a DuckDB round-trip). `tests/thucia/cli/test_cli.py` probes the CLI (parser/dispatch wiring + the case-aggregation steps against a temp project, GADM mocked); `tests/thucia/pipeline/` was removed (superseded by the stage and e2e tests).
- The suite was written "probingly": tests assert real correctness properties (WIS analytic values and monotonicity, quantile ordering, ensemble weight normalization, adapter residual shrinkage, cache round-trips) and have surfaced + fixed real bugs. Keep this style: prefer asserting properties over smoke-testing.
- Known hardening already applied (add regression tests if you touch these): `DataFrame.head()` was broken; `sanitise_covariates()` crashed on string/Timestamp `start_date`; `run_model()` had mutable default args; `apply_weights_to_forecasts()` crashed on `pd.Period` dates; `r2_score()` returned `-inf` on constant targets; `wis_bracher()` didn't implement its documented `model` auto-grouping; `sarima(retrain=False)` passed `quantiles` to `AutoARIMA.fit()` (constructor arg only) and darts' fixed-order `ARIMA` can't emit likelihood parameters — the fixed-order branch now samples (`num_samples`) and DartsBase converts samples→quantiles; `tft`/`tide` `build_model()` ignored the `horizon` kwarg DartsBase passes and used `last_points_only=False` (list output) — both fixed to match the other darts models; `SQLiteCache` leaked sqlite3 connections (`with sqlite3.connect(...) as conn` commits but never closes — now closed via `_connect`); `score_model` crashed on a horizon with no prediction rows (now skips empty horizons); the adapter `_prepare_fit_table` crashed on Period-dated `cutoff_date` (now Period-aware) and warned on the mask path (now copies); `write_nc` crashed on a Period `Date` column (netCDF can't encode Period dtype) and `read_nc` never restored Period columns (xarray drops Dataset attrs in `to_dataframe()`) — both now round-trip Periods via `_df_to_xarray`/`_restore_period_column`.
- Forecast tests: `tests/thucia/core/models/forecast_data.py` generates synthetic seasonal monthly data (categorical GID, NaN-free covariates, `n_periods=60` default; `freq`/`season_length` supported for weekly/daily fixtures). Fits are kept small by forecasting only a short trailing window (last ~6 periods); xgboost needs `lags=48` history, and multi-horizon `output_chunk_length=12` needs ≥60 periods of training. `test_darts_base.py` drives DartsBase with a mock subclass (no training); `test_forecast_e2e.py` runs `run_model` for baseline/movavg/sarima(retrain T+F)/xgboost/tcn/nhits/tft on the small fixture and asserts the canonical quantile grid + scoreability; `test_forecast_slow.py` (`-m slow`) fits nbeats (~22s), xgboost multi-horizon (~70s), sarima weekly (season_length=52), and timesfm (network checkpoint); `tests/thucia/core/validation/test_backtest.py::test_sarima_backtest_slow` runs a real-model backtest across a couple of cutoffs.
- Known instability: darts `TiDEModel` (`tide`) diverges on small synthetic data (inf/NaN across seeds) — it has no fit test; only its signature contract is enforced. nbeats is the slow default-able model and lives in `slow`.
- **Cadence support**: monthly/weekly/daily are supported end-to-end. `aggregate_cases(freq=...)` and `cases_per_period` handle any period freq (weekly anchors like `W-SAT`/`W-SUN` preserved); `DartsBase` derives the darts freq from the Period dtype (monthly uses `ME` for darts, `M` for Period conversions — the dtype-name regex `period\[(.+)\]` gives the Period-valid string); `movavg` groups seasons by month/ISO-week/day-of-year; `sarima` takes `season_length` (auto-detected M→12, W*→52, D→365, overridable; also in `PipelineConfig`). `forecast_data.make_forecast_df(freq=..., season_length=...)` builds cadence-aware fixtures. Covariate sources declare a `granularity` (worldclim/edo/noaa are `"M"`); on finer case grids `merge_geo_sources` interpolates their values onto every period (method configurable via `PipelineConfig.covariate_interpolation`, default `"linear"`; also `"ffill"`/`"bfill"`) and raises a `UserWarning`.
- `tests/thucia/core/models/test_models_registry.py` enforces the model contract: every advertised model resolves a valid `SPEC` (with `supports` ⊆ `SUPPORTED_KWARGS`), each spec's declared knobs + the common kwargs bind on the callable signature (via `inspect.signature().bind_partial`), only baseline/movavg are `fast`, and every model uses a list-form `horizons` default. `tests/thucia/core/test_quantiles.py` pins the canonical grid to a single object across all import paths and checks `quantile_sum_fast`'s default matches it.
- Coverage is ~81% incl. the forecast tests (`darts/__init__`, `sarima`, `tcn`, `nhits`, `tft`, `xgboost`, `movavg`, `baseline`, the `core/pipeline` stages, `registry`, `cli/__init__`/`cli/steps.py`, `geo/stats.py`, `geo/sources/worldclim.py`, `models/utils/covariates.py`, `models/utils/adapter.py`, `validation/`, and `viz/` are 92-100%). The remaining gaps (`viz/` dashboard Streamlit pages, `cli/steps.py` launch subprocess paths, `core/__init__.py`, `models/inla.py`, `models/chronos.py`) are documented; `nbeats`/`tide` bodies are covered only by the `slow` marker (or, for tide's fit, not at all due to instability). `uv run pytest --cov=thucia` works locally via the `-p thucia_pytest_bootstrap` plugin in `addopts`: it pre-imports duckdb before pytest-cov starts, because coverage's source discovery imports `thucia` inside a `sys.modules`-saving block whose cleanup corrupts duckdb's multi-module extension submodules (`_duckdb._sqltypes`) on CPython 3.13 ("`_duckdb` is not a package").
- The suite is warning-clean: library-originated pandas FutureWarnings/deprecations were fixed, and known third-party noise (torch/statsmodels/darts) is suppressed via `filterwarnings` in `pyproject.toml`. `uv run pytest -W error::FutureWarning` fails only on a torch-internal `treespec` deprecation.
- `tests/thucia/core/containers/test_containers.py` builds/runs an alpine image and fails if no container runtime is running — skip it locally if Docker/Podman isn't up.
